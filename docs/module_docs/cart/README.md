# Cart 模块核心说明

本文档是 Cart 模块的核心说明文档，提供了模块的概述、路由入口、依赖关系等关键信息，以便其他开发者能够理解和集成本模块。

## 1. 模块概述 (Brief Overview)

**一句话描述**: Cart 模块负责管理用户的购物车功能，包括添加商品、修改数量、移除商品、应用优惠券和启动结算流程。

**主要功能点**:
- 查看购物车中的商品列表
- 添加商品到购物车
- 修改购物车中商品的数量
- 移除购物车中的商品
- 清空购物车
- 应用/移除优惠券
- 查看购物车摘要信息（总价、商品数量等）
- 启动结算流程

Cart 模块采用 Clean Architecture 架构，清晰地分离了数据层、领域层和表现层，使得模块具有高度的可测试性和可维护性。模块内部使用 BLoC 模式进行状态管理，通过依赖注入实现组件间的解耦。

## 2. 路由入口与参数 (Routing Entry Points & Parameters)

### 如何进入本模块:

- **路径**: `/cart`, **名称**: `cart` (购物车页面，无需参数)

### 必需参数:

- 购物车页面不需要任何参数

路由定义位于 `lib/features/cart/presentation/routes/cart_routes.dart` 文件中，遵循项目的模块化路由策略。

## 3. 外部依赖说明 (External Dependencies)

### 核心服务依赖:

- **`NetworkInfo`**: 用于检查网络连接状态，决定是否从本地缓存获取数据
- **`Failure`**: 用于统一错误处理
- **`UseCase`**: 用于实现领域层用例
- **`GoRouter`**: 用于路由导航
- **`GetIt`**: 用于依赖注入
- **`SharedPreferences`**: 用于本地缓存购物车数据
- **`http.Client`**: 用于网络请求

### 跨模块依赖:

Cart 模块设计为最小化跨模块依赖，主要通过以下方式实现:

- 使用导航服务接口解耦导航逻辑
- 使用仓库接口解耦数据获取逻辑
- 不直接依赖其他功能模块的实现，只依赖核心层提供的接口和服务

然而，Cart 模块确实需要以下跨模块依赖:

- **`Auth` 模块**: 需要用户认证状态和 `userId` 来管理其购物车
- **`Product/Item` 模块**: 需要调用 `IProductRepository` 获取商品信息（特别是实时价格、库存状态、是否下架）用于展示、计算和验证

## 4. 调用的主要 API (APIs Consumed)

Cart 模块调用以下后端 API 端点:

- **`GET /api/shop/cart/list`**: 获取购物车列表
  - 用途: 获取当前用户的购物车内容
  - 参数: 无需参数，通过 Authorization 头部传递用户令牌

- **`POST /api/shop/cart/modify-number`**: 添加商品到购物车或修改数量
  - 用途: 添加新商品到购物车或修改已有商品的数量
  - 参数: `productId` (商品ID), `variantId` (规格ID, 可选), `number` (数量)

- **`POST /api/shop/cart/deleteOne`**: 删除单个购物车商品
  - 用途: 从购物车中移除单个商品
  - 参数: `id` (购物车项ID)

- **`POST /api/shop/cart/delete`**: 批量删除购物车商品
  - 用途: 从购物车中批量移除商品
  - 参数: 购物车项ID数组

API 的详细请求/响应结构可以参考 `design-info/api/backend-api.json` 文档。

## 5. 对外暴露的服务/接口 (Exposed Services/Interfaces)

Cart 模块不直接向其他模块提供服务或数据，而是通过以下方式与其他模块交互:

- **路由系统**: 其他模块可以通过路由系统导航到 Cart 模块的页面
- **事件总线**: Cart 模块可能会发布一些事件，其他模块可以订阅这些事件

Cart 模块的设计原则是高内聚低耦合，尽量减少模块间的直接调用。

## 6. 注意事项/配置要求

- **网络权限**: 本模块需要网络权限来获取购物车数据和执行购物车操作
- **缓存策略**: 购物车数据会在本地缓存，以便在网络不可用时仍能显示内容
- **用户认证**: 购物车功能需要用户登录，未登录用户将被重定向到登录页面
- **性能考量**: 购物车操作（如添加、修改数量）采用乐观更新策略，提高用户体验

## 8. 资源管理说明 (Resource Management)

### 模块资源列表:

Cart 模块主要使用系统图标和文本资源，不包含特定的图片资源。

- 所有与 Cart 模块相关的资源应使用 `cart_` 前缀
- 图标资源应使用 `icon_cart_` 前缀
- 图片资源应使用 `img_cart_` 前缀

### 资源存放位置:

- 模块特有图标存放在 `assets/icons/cart/` 目录下
- 模块特有图片存放在 `assets/images/cart/` 目录下
- 共享图标使用 `assets/icons/common/` 目录下的资源

## 9. 已知问题与解决方案 (Known Issues & Solutions)

### 已知限制:

- **优惠券功能**: 当前优惠券功能是占位实现，后端API可能尚未完全支持
- **结算流程**: 结算流程依赖于尚未实现的Checkout模块
- **库存检查**: 当前实现中，库存检查仅在加载购物车时进行，可能不够实时

### 临时解决方案:

- 使用本地缓存解决网络不可用时的数据显示问题
- 使用乐观更新策略提高用户体验

### 修复计划:

- 计划在后续版本中完善优惠券功能
- 计划在后续版本中实现与Checkout模块的完整集成
- 计划在后续版本中实现实时库存检查

### 开发者注意事项:

- 购物车操作API的响应格式可能会随后端更新而变化，需要密切关注
- 购物车与用户认证强相关，确保在使用购物车功能前检查用户登录状态

## 10. 跨模块通信机制 (Cross-Module Communication)

### 输出事件/通知:

- **`CartUpdatedEvent`**: 当购物车内容更新时发出，其他模块可能需要响应此事件以更新UI（如购物车图标上的数量标记）
- **`CheckoutInitiatedEvent`**: 当用户启动结算流程时发出，Checkout模块需要监听此事件以接收结算数据

### 输入事件/通知:

- **`UserLogoutEvent`**: 当用户登出时，Cart模块需要清除购物车数据
- **`ProductPriceChangedEvent`**: 当商品价格变更时，Cart模块需要更新购物车中的商品价格

### 通信方式:

Cart模块使用事件总线机制实现跨模块通信，相关代码位于 `lib/core/event/app_events.dart`。

### 直接依赖:

Cart模块不直接依赖其他模块的服务或数据，而是通过以下方式实现解耦:

- 使用依赖注入注册和获取服务
- 使用接口定义而非具体实现
- 使用事件总线进行松耦合通信
