# 项目文档文件夹 (`docs/`) 说明

`docs` 文件夹是项目主要的文档存放目录，包含了项目开发、设计、规范和模块化等方面的各类信息。其目的是为团队成员提供一个集中的知识库，方便查阅和理解项目相关的背景、决策和规范。

## 文件夹结构概览

```
docs/
├── BD/
├── dev/
└── module_docs/
```

## 各主要文件夹说明

### 1. `BD/` (边界分析 Boundary Analysis)

*   **用途**：此文件夹存放与项目或模块功能边界相关的分析文档。边界分析旨在明确系统或组件的输入、输出、交互接口以及其在特定上下文中的限制和约束条件。这对于定义需求范围、识别潜在风险和设计健壮的接口至关重要。
*   **内容可能包括**：
    *   不同模块间的接口定义和数据流分析。
    *   系统与外部依赖（如第三方服务）的交互边界。
    *   用户场景下的输入有效性边界和异常处理分析。
    *   性能或资源使用的边界条件。
*   **建议**：查阅此文件夹内的具体文件以获取特定功能或模块的边界分析详情。

### 2. `dev/` (开发文档)

*   **用途**：此文件夹是开发文档的核心，包含了项目开发过程中的技术决策、规范、策略、分析报告以及辅助开发的资源文件。
*   **文件树及分工说明**：

    ```
    dev/
    ├── api_usage_summary_cn.md               # API 使用概要（中文）：总结项目中后端 API 的调用方式、认证、参数、返回格式及错误处理等规范和注意事项。
    ├── brown.jpg                             # 图片资源 (brown.jpg)：一个 JPG 格式的图片文件，具体用途未知，可能与 UI 设计、示例图或特定文档的插图有关。
    ├── caching_and_local_storage_strategy_cn.md # 缓存与本地存储策略（中文）：阐述项目中数据缓存和本地存储的总体策略、选型依据及使用规范。
    ├── frontend.md                           # 前端文档：可能包含前端整体架构设计、技术选型、编码规范、组件库使用指南等。
    ├── human_work_todo.md                    # 人工待办事项：记录那些无法通过自动化工具完成，需要人工介入和处理的任务、问题或决策点。
    ├── internationalization_strategy_cn.md   # 国际化策略（中文）：详细说明项目如何实现多语言支持，包括文案提取、翻译流程、语言包管理等。
    ├── merge_integration_troubleshooting.md  # 合并与集成问题排查：收集和记录代码合并、模块集成过程中常见问题及其解决方案。
    ├── module_merge_checklist_cn.md          # 模块合并检查清单（中文）：提供模块合并到主干前必须检查和确认的事项。
    ├── modular_routing_strategy_cn.md        # 模块化路由策略（中文）：定义模块化架构下页面路由的管理方式，包括跳转、参数传递、注册和发现。
    ├── navigation_service_abstraction_cn.md  # 导航服务抽象（中文）：描述项目导航服务的抽象层设计，解耦具体路由实现。
    ├── order_list_caching_details_cn.md      # 订单列表缓存详情（中文）：详细说明订单列表功能的缓存机制、触发、更新及过期策略。
    ├── preliminary_analysis.md               # 初步分析报告：项目初期或模块开发前的需求分析、技术可行性分析、风险评估等。
    ├── RouteScreenMapping.md                 # 路由与屏幕映射关系：列出所有定义的路由路径及其对应的页面组件。
    ├── start.md                              # 项目启动指南：为新成员或新环境部署提供快速入门指引。
    ├── tech_stack.md                         # 技术栈：列出项目采用的主要编程语言、框架、库、工具和服务。
    ├── 合并前的准备.md                       # 合并前的准备工作：开发者在执行代码合并操作前需完成的步骤。
    ├── 目录结构参考.md                       # 目录结构参考：提供项目推荐的或当前遵循的文件夹和文件组织规范。
    ├── 图标.jpg                              # 图标资源 (图标.jpg)：项目中使用的图标的位图版本。
    ├── 图标.svg                              # 图标资源 (图标.svg)：项目中使用的图标的矢量图版本。
    ├── 模块todo.md                           # 模块待办事项：按模块或功能点划分，记录未完成的开发任务、已知缺陷或改进计划。
    └── 模块开发核心工作流.md                 # 模块开发核心工作流程：定义标准化的模块开发流程，从需求到发布的各个阶段。
    ```

### 3. `module_docs/` (模块文档)

*   **用途**：此文件夹用于存放各个独立功能模块的详细设计文档、接口说明、使用指南或特定的技术实现细节。每个子目录或文件通常对应项目中的一个具体模块（例如：用户认证模块、订单处理模块、AI 助手模块等）。
*   **内容可能包括**：
    *   模块的详细设计文档。
    *   模块对外暴露的 API 接口文档。
    *   模块的使用案例和示例代码。
    *   特定复杂逻辑或算法的实现说明。
    *   模块相关的数据库表结构设计（如果适用）。
*   **建议**：当需要深入了解某一特定模块时，应首先查阅此文件夹下对应的模块文档。

## 如何维护本文档

本文档（`docs/README.md`）旨在作为 `docs` 文件夹的入口和指南。当 `docs` 文件夹的结构发生变化，或者 `dev/` 文件夹中增加了新的核心文档时，请及时更新本文档以保持其准确性。
