# Flutter 项目核心技术选型

本文档记录了 DSKK-Flutter 重构项目最终确定的核心技术选型，主要基于**开发便捷性**和**降低认知负载**的原则，同时兼顾 Clean Architecture 和模块化的需求。

## 1. 状态管理 (State Management)

**选型**: **Bloc** (`bloc`, `flutter_bloc`)

**理由**:

*   **明确的事件驱动流程**: Bloc 强制使用事件来触发状态变更，使得状态变更的来源和流程非常清晰，易于跟踪和调试。
*   **可测试性**: 其清晰的输入（事件）和输出（状态）使得单元测试和集成测试相对容易编写。
*   **成熟稳定**: Bloc 是一个非常成熟和广泛使用的库，拥有大量的文档、教程和社区支持。
*   **与现有代码兼容**: 基于当前模块已有的 Bloc 相关代码基础，继续使用 Bloc 可以减少重构成本，加速开发进程。
*   **（修订说明）**: *此选型是基于现有 AI_Docs 模块代码的实际情况进行的修订，优先保证当前模块的开发效率和一致性。*

## 2. 依赖注入 (Dependency Injection - DI)

**选型**: **get_it** + **injectable**

**理由**:

*   **自动化配置**: `injectable` 通过注解和代码生成，极大地简化了 `get_it` 的依赖注册过程，减少手动编写和维护注册代码的负担。
*   **类型安全**: 结合 `get_it` 提供了强大的类型安全的依赖获取。
*   **解耦**: 作为服务定位器，`get_it` 与 Flutter Widget 树解耦，非常适合在 Clean Architecture 的不同层（Data, Domain, Presentation）之间注入依赖。
*   **降低认知负载**: 一旦配置好生成器，日常使用只需注解和获取实例，心智负担较低。

## 3. 导航 (Navigation)

**选型**: **go_router**

**理由**:

*   **官方推荐**: 由 Flutter 团队维护，社区支持良好。
*   **声明式路由**: 提供基于路径 (URL-like) 的声明式路由，易于理解和配置，特别适合有 Web 开发背景或需要 Web 支持的应用。
*   **功能强大**: 轻松处理深层链接、参数传递、重定向和嵌套导航。
*   **相对简单**: 相较于手动实现 Navigator 2.0 或 `auto_route` 的代码生成配置，`go_router` 的核心概念和基本配置相对更容易上手。
*   **无需强制代码生成**: 核心功能不强制依赖代码生成，降低了构建复杂度和初始设置障碍。

## 总结

该技术栈 (`Bloc` + `get_it/injectable` + `go_router`) 在提供强大功能和良好架构支持的同时，力求简化开发流程、减少模板代码和降低学习曲线，以适应团队规模和快速开发的需求。
