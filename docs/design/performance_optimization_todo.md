# 性能优化 TODO

## 概述

本文档记录了 DSKK Flutter 应用的性能优化任务清单，基于当前性能分析结果制定。优化目标是提升应用响应速度、减少网络请求、改善弱网体验。

## 优化任务清单

#### 1.1 创建统一的内存缓存管理器
- [ ] 实现 `MemoryCacheService` 基础类
  - [ ] 支持 TTL（生存时间）配置
  - [ ] 实现 LRU（最近最少使用）淘汰策略
  - [ ] 支持缓存大小限制（建议：50MB）
  - [ ] 提供缓存命中率统计
  - [ ] 支持缓存分组（按模块隔离）

- [ ] 编写单元测试

#### 1.2 基于业务优先级的缓存策略

**高频访问数据（需要立即缓存）：**
- [ ] 用户个人信息缓存
  - [ ] 当前用户资料（TTL: 会话期间有效）
  - [ ] 用户认证状态（TTL: 会话期间有效）

#### 2.2 API 缓存策略配置

**需要缓存的 API：**
- [ ] 用户信息 API (`/api/user/info`)：缓存 30 分钟
- [ ] 商品列表 API (`/api/product/list`)：缓存 5 分钟
- [ ] 商品详情 API (`/api/product/detail`)：缓存 10 分钟
- [ ] 商品分类 API (`/api/category`)：缓存 60 分钟
- [ ] 收藏列表 API (`/api/favorites`)：缓存 10 分钟
- [ ] 卖家信息 API (`/api/seller/info`)：缓存 20 分钟

**条件缓存的 API：**
- [ ] AI 对话列表 (`/model/chat/list`)：缓存 5 分钟（仅列表结构，不影响新对话创建）
- [ ] AI 历史消息 (`/model/chat/messages`)：
  - [ ] 最近对话（24小时内）：缓存 2 分钟
  - [ ] 历史对话（超过24小时）：缓存 30 分钟

**不应缓存的 API：**
- [ ] AI 推荐服务 (`/recsys/conversation/recommend`)：**不缓存**
  - 原因：基于对话上下文实时生成，每次对话内容不同
  - 包含用户行为分析，需要最新数据
  - 有分配状态追踪，避免重复推荐
- [ ] AI 聊天流 (`/model/chat` SSE)：**不缓存**
  - 原因：实时流式响应
- [ ] AI 服务分配 (`/model/chat/allocate`)：**不缓存**
  - 原因：涉及商家匹配和聊天室创建
- [ ] 订单状态更新类 API：**不缓存**
- [ ] 支付相关 API：**不缓存**
- [ ] 实时聊天 WebSocket：**不缓存**

**特殊处理：**
- [ ] 订单列表：继续使用现有的 Drift 数据库缓存策略
- [ ] 图片资源：使用 `cached_network_image` 的独立缓存机制
- [ ] 静态配置（如微信配置）：应用启动时加载，全程缓存

## 注意事项

### 开发原则
1. **渐进式优化**：先实现基础功能，再逐步优化
2. **数据驱动**：基于实际性能数据做决策，避免过度优化
3. **用户优先**：优先优化用户可感知的性能问题
4. **兼容性考虑**：确保低端设备也能正常运行

### 技术要点
1. **缓存一致性**：
   - 实现缓存失效机制
   - 处理数据更新时的缓存同步
   - 避免展示过期数据

2. **内存管理**：
   - 监控内存使用情况
   - 及时释放不需要的资源
   - 实现缓存大小限制

3. **错误处理**：
