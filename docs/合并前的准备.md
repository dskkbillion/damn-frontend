# 模块文档编写指南

**目的:** 为了促进团队协作、方便模块集成、以及让其他开发者能快速理解和使用你负责的功能模块，我们要求每个功能模块（Feature）都需要编写并维护一些必要的说明文档。

**要求:** 请将与你负责的功能模块相关的**所有**说明文档（Markdown格式 `.md`）集中放置在**项目根目录下的 `docs/module_docs/` 文件夹内，并以模块名创建子文件夹**进行归类。

**文档存放结构示例:**

```
docs/
├── module_docs/                # 模块专属文档的根目录（说明和todo什么的全放这）
│   ├── orders/                 # 订单模块的文档
│   │   ├── README.md           # (必需) 订单模块核心说明
│   │   ├── order_list_caching_details_cn.md # (示例) 订单列表缓存说明
│   │   └── ...                 # (其他订单模块相关文档)
│   ├── aichat/                   # aichat模块的文档
│   │   ├── README.md           # (必需) aichat模块核心说明
│   │   └── ...
│   ├── seller/            # seller模块的文档
│   │   ├── README.md           # (必需) seller模块核心说明
│   │   └── ...
│   └── ...                     # 其他模块的文档目录
├── BD/                         # 边界定义文档 (保持不变)
├── api_usage_summary_cn.md     # 全局 API 总结 (保持不变)
├── caching_and_local_storage_strategy_cn.md # 全局缓存策略 (保持不变)
├── modular_routing_strategy_cn.md   # 全局路由策略 (保持不变)
├── module_merge_checklist_cn.md # 模块合并清单 (保持不变)
├── 合并前的准备.md # 本指南 (你正在阅读的文件)
└── ... (其他全局文档)
```

## 模块核心说明文档 (`<模块名>/README.md`)

在 `docs/module_docs/<你的模块名>/` 目录下，**必须**包含一个 `README.md` 文件。此文件是其他开发者了解你模块的关键入口，请至少包含以下**核心内容**，重点说明**模块间耦合与集成**所需的信息：

### 1. 模块概述 (Brief Overview)

*   **一句话描述:** 简要说明这个模块的核心功能和职责。
    *   *示例: "处理用户认证流程，包括登录、注册、Token管理。"*
*   **(可选) 主要功能点:** 列出该模块包含的主要用户可见功能或子流程。
    *   *示例:* 
        *   *- 手机号+验证码登录*
        *   *- 密码登录*
        *   *- 用户注册*
        *   *- 忘记密码*

### 2. 路由入口与参数 (Routing Entry Points & Parameters)

*   **如何进入本模块:** 列出从**外部**导航进入本模块**主要页面**的路由路径 (Path) 和名称 (Name)。
*   **必需参数:** 清晰说明每个入口路由**必须**接收哪些路径参数 (`:id`)、查询参数 (`?key=value`) 或通过 `extra` 传递的对象及其类型。
    *   *示例 (订单模块):*
        *   *- 路径: `/orders`, 名称: `orders` (买家订单列表，无需参数)*
        *   *- 路径: `/orderDetail/:orderId`, 名称: `orderDetail` (买家订单详情，需要路径参数 `orderId` (String))* 
        *   *- 路径: `/seller/orders`, 名称: `sellerOrders` (卖家订单列表，无需参数)*
        *   *- 路径: `/seller/orders/:orderId`, 名称: `sellerOrderDetail` (卖家订单详情，需要路径参数 `orderId` (String))* 
        *   *- 路径: `/selectAfterSalesType/:orderItemId`, 名称: `selectAfterSalesType` (选择售后类型，需要路径参数 `orderItemId` (String) **和** `extra` 中的 `OrderItem` 对象)*
*   **参考:** 路由定义应遵循 `docs/modular_routing_strategy_cn.md` 规范，具体实现在你模块的 `presentation/routes/` 目录下。

### 3. 外部依赖说明 (External Dependencies)

*   **核心服务依赖:** 列出本模块运行所**依赖**的 `lib/core/` 下的核心服务或接口。
    *   *示例:*
        *   *- `IAuthRepository` (用于获取当前用户状态)*
        *   *- `CoreDioClient` (通过 Repository 间接依赖，用于网络请求)*
        *   *- `INavigationService` (用于模块内部或跨模块导航)*
*   **跨模块依赖:** 列出本模块是否直接依赖**其他 Feature 模块**提供的服务、Bloc 或数据实体？ (应尽量避免，若有需说明)
    *   *示例: "依赖 `UserProfile` 模块获取用户昵称显示。" (这种情况需谨慎评估)*

### 4. 调用的主要 API (APIs Consumed)

*   **接口列表:** 列出本模块业务逻辑实现所调用的主要后端 API 端点 (Endpoint Path 即可)。
*   **目的:** 简述每个 API 的主要用途。
*   **细节参考:** 指明详细的请求/响应结构、认证要求等可以参考全局的 `docs/api_usage_summary_cn.md` 文档。
    *   *示例 (订单模块):*
        *   *- `POST /api/shop/order/list` (获取订单列表)*
        *   *- `GET /api/shop/order/detail` (获取订单详情)*
        *   *- `GET /api/shop/order/cancel` (取消订单)*
        *   *- (更多接口...)*
        *   *- (详细信息请参考 `docs/api_usage_summary_cn.md`)*

### 5. (可选) 对外暴露的服务/接口 (Exposed Services/Interfaces)

*   如果你的模块设计为向其他模块提供服务或数据 (例如，认证模块提供 `getCurrentUser()` 方法)，请在此说明暴露的接口或方法及其用法。
    *   *(应尽量减少模块间的直接调用，优先通过核心服务或事件总线解耦)*

### 6. (可选) 注意事项/配置要求

*   运行或使用本模块是否有特殊的环境要求、配置步骤或注意事项？
    *   *示例: "本模块功能需要设备开启定位权限。"*

### 7. 依赖包使用说明 (Package Dependencies)

*   **依赖包清单:** 列出本模块实现过程中使用的所有主要依赖包（不包括Flutter/Dart核心库）。
*   **版本信息:** 标注每个依赖包所使用的版本。
*   **用途说明:** 简要描述每个依赖包在模块中的主要用途。
*   **使用位置:** 指明在模块的哪些文件或功能中使用了这些依赖包。
    *   *示例 (订单模块):*
        *   *- `flutter_bloc: ^8.1.3` - 用于状态管理，在所有Bloc文件中使用*
        *   *- `equatable: ^2.0.5` - 用于简化相等性比较，在所有实体类和状态类中使用*
        *   *- `cached_network_image: ^3.2.3` - 用于带缓存的图片加载，在`OrderItemCard`和`ProductDetailView`中使用*
        *   *- `drift: ^2.10.0` - 用于订单列表本地缓存实现，在`OrderLocalDataSourceImpl`中使用*
        *   *- `path_provider: ^2.0.15` - 配合drift提供数据库存储位置，在`AppDatabase`中使用*

### 8. 资源管理说明 (Resource Management)

*   **模块资源列表:** 列出本模块使用的所有特定资源文件（图片、图标、字体、JSON数据等）。
*   **资源命名规范:** 说明模块资源的命名约定，以避免与其他模块资源冲突。
    *   *示例: "所有订单模块的图片资源均使用 `order_` 前缀，如 `order_status_delivered.png`"*
*   **资源存放位置:** 明确指出这些资源的存放路径，是在模块内部还是在全局资源目录。
    *   *示例: "模块特有图标存放在 `assets/images/orders/` 目录下，共享图标使用 `assets/images/common/`"*
*   **资源使用方式:** 简要描述如何在代码中正确引用这些资源。
    *   *示例: "通过 `Assets.images.orders.statusDelivered.image()` 方式引用（使用了assets_gen生成的访问器）"*

### 9. 已知问题与解决方案 (Known Issues & Solutions)

*   **已知限制:** 列出模块当前存在的已知问题、限制或不完善之处。
    *   *示例: "在网络极慢情况下，订单列表可能出现短暂白屏现象"*
*   **临时解决方案:** 说明针对这些问题的临时解决方案或规避措施。
    *   *示例: "使用loading占位图解决图片加载失败问题"*
*   **修复计划:** 如果有计划在未来版本中修复的问题，请说明预计修复时间和方案。
    *   *示例: "计划在v2.0版本通过预加载方式解决首次加载缓慢问题"*
*   **开发者注意事项:** 提醒其他可能使用或维护此模块的开发者需要注意的事项。
    *   *示例: "订单状态更新逻辑目前不支持部分发货状态，需等待后端API更新"*

### 10. 跨模块通信机制 (Cross-Module Communication)

*   **输出事件/通知:** 列出此模块可能发出的、其他模块可能需要响应的事件或通知。
    *   *示例: "订单支付成功后，会发出 `OrderPaidEvent`，购物车模块需监听此事件以清空购物车"*
*   **输入事件/通知:** 列出此模块需要响应的、由其他模块发出的事件或通知。
    *   *示例: "本模块监听 `UserLogoutEvent` 以清除当前用户的订单缓存"*
*   **通信方式:** 说明使用何种机制实现模块间通信（如事件总线、全局状态管理、服务注入等）。
    *   *示例: "使用 `event_bus` 包实现跨模块事件传递，相关代码位于 `lib/core/event/app_events.dart`"*
*   **直接依赖:** 明确说明本模块是否直接依赖其他模块的服务或数据（应尽量避免），若有则详细说明。
    *   *示例: "订单确认页面需直接调用地址模块的 `AddressRepository` 获取用户地址信息"*
