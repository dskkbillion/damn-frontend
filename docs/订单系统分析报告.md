# 订单系统分析报告

## 一、订单状态定义

### 后端订单状态枚举（OrderStatusEnum）
```java
- awaitingPayment (待付款)
- awaitingSubmission (等待提交要求) 
- buyAwaitingSubmission (买家材料重传)
- awaitingStart (等待开始)
- awaitingDelivery (等待卖家交付)
- awaitingConfirmation (交付待确认)
- sellerSupplementaryMaterials (卖家重新交付)
- applyForRefuse (申请拒绝)
- afterSale (售后中)
- AfterSaleRejection (售后拒绝)
- applyingForMediation (平台介入)
- awaitingEvaluation (等待评价)
- orderCompleted (订单成功结束)
- canceled (已取消)
```

## 二、订单状态转换逻辑

### 主要状态转换流程
1. **创建订单**: → `awaitingPayment`
2. **支付成功**: `awaitingPayment` → `awaitingSubmission`
3. **买家提交材料**: `awaitingSubmission` → `awaitingStart`
4. **卖家确认接单**: `awaitingStart` → `awaitingDelivery`
5. **卖家发货**: `awaitingDelivery` → `awaitingConfirmation`
6. **买家确认收货**: `awaitingConfirmation` → `awaitingEvaluation`
7. **完成评价**: `awaitingEvaluation` → `orderCompleted`

### 特殊状态转换
- **取消订单**: 多个状态 → `canceled`
- **申请售后**: 多个状态 → `afterSale`
- **材料问题**: → `buyAwaitingSubmission` 或 `sellerSupplementaryMaterials`
- **平台介入**: → `applyingForMediation`

## 七、关键API接口汇总

- 材料列表: POST `/api/project/orderMaterials/list`

### 订单交付接口（OrderDelivery）
- 提交交付: POST `/api/project/orderDelivery/add`
- 交付列表: POST `/api/project/orderDelivery/list`

## 八、订单状态转换详细条件

### 状态转换规则和限制
1. **取消订单限制**：
   - 允许取消的状态：awaitingPayment, awaitingSubmission, awaitingStart, buyAwaitingSubmission
   - 其他状态不允许取消
   - 取消后触发退款流程

2. **确认收货限制**：
   - 当前状态必须为 awaitingConfirmation
   - 只有买家本人可以确认收货
   - 确认后自动进入待评价状态

3. **卖家发货限制**：
   - 当前状态必须为 awaitingDelivery
   - 发货后订单进入 awaitingEvaluation 状态（注意：代码中有误，应该是 awaitingConfirmation）

4. **卖家接单限制**：
   - 当前状态必须为 awaitingStart
   - 只有订单所属卖家可以操作
   - 接单后进入 awaitingDelivery 状态

### 自动化处理机制
1. **自动取消**：订单创建后30分钟（可配置）未支付将自动取消
2. **自动确认收货**：发货后一定天数（可配置）自动确认收货
3. **自动完成**：确认收货后自动进入待评价状态

## 九、买家端动态内容组件详解

### 1. WaitingActionArea（等待操作区）
- **适用状态**：awaitingStart, awaitingDelivery
- **功能**：显示等待卖家操作的提示信息
- **内容**：
  - 等待开始服务提示
  - 卖家备货中提示
  - 买家备注信息（如果有）

### 2. OrderRequirementSubmissionForm（需求提交表单）
- **适用状态**：awaitingSubmission, buyAwaitingSubmission
- **功能**：买家提交订单所需材料
- **特性**：
  - 支持文本输入（两个输入框）
  - 支持文件附件上传
  - 自动保存草稿功能（使用SharedPreferences）
  - 防重复提交机制

### 3. DeliveryConfirmationArea（交付确认区）
- **适用状态**：awaitingConfirmation
- **功能**：显示交付信息，等待买家确认
- **内容**：交付状态信息、物流信息等

### 4. OrderEvaluationForm（订单评价表单）
- **适用状态**：awaitingEvaluation
- **功能**：买家对订单进行评价
- **特性**：评分、评价内容输入等

### 5. AfterSaleInfoArea（售后信息区）
- **适用状态**：afterSale, AfterSaleRejection
- **功能**：显示售后处理进度和状态

### 6. OrderCompletionSummary（订单完成总结）
- **适用状态**：orderCompleted
- **功能**：显示订单完成信息总结

## 十、卖家端动态内容组件详解

## 十一、订单事件机制

### 核心事件类型
1. **OrderCreateBeforeEvent/AfterEvent**：订单创建前后
2. **OrderPayBeforeEvent/AfterEvent**：订单支付前后
3. **OrderShipBeforeEvent/AfterEvent**：订单发货前后
4. **OrderCompleteBeforeEvent/AfterEvent**：订单完成前后
5. **OrderCancelBeforeEvent/AfterEvent**：订单取消前后
6. **OrderDeleteBeforeEvent/AfterEvent**：订单删除前后

### 通知消息类型
1. **NewOrderMessage**：新订单通知（发送给卖家）
2. **OrderShipMessage**：发货通知（发送给买家）
3. **RemindShipMessage**：提醒发货通知（发送给卖家）
4. **OrderCompleteMessage**：订单完成通知

### 事件监听器
- MemberCommissionListener：会员佣金处理
- SharedMemberOrderCommissionListener：分享会员佣金
- SharedProductOrderCommissionListener：分享商品佣金
- SendMessageOrderListener：发送消息通知
- OrderEventListener：订单事件处理
- RefundMoneyEventListener：退款资金处理

## 十二、订单退款机制

### 退款接口
- 申请售后：POST `/api/shop/order-refund/apply`
- 售后审核：POST `/api/shop/order-refund/audit`
- 售后列表：POST `/api/shop/order-refund/list`
- 卖家售后列表：POST `/api/shop/order-refund/listTenant`
- 售后发货：POST `/api/shop/order-refund/ship`

### 退款类型（RefundTypeEnum）
- ONLY_MONEY：仅退款
- MONEY_AND_GOODS：退货退款

### 退款状态（RefundStateEnum）
- WAIT_AUDIT：等待审核
- AUDIT_REFUSED：审核拒绝
- 其他状态...

### 退款角色（RefundMemberTypeEnum）
- buyer：买家发起
- seller：卖家处理

### 审核类型（RefundAuditTypeEnum）
- seller：卖家审核
- platform：平台审核

### 退款流程
1. 买家申请退款 → 创建退款单
2. 卖家审核 → 同意/拒绝
3. 如果拒绝且已发货 → 自动转平台审核
4. 平台介入处理 → 最终裁决

## 十三、订单支付流程

### 支付页面流程（OrderConfirmPage）
1. **订单确认**：
   - 显示商品信息
   - 选择支付方式（支付宝/微信）
   - 计算订单金额

2. **创建订单**：
   - 调用 CreateOrderEvent
   - 显示"创建订单中..."加载框
   - 获取订单ID

3. **发起支付**：
   - 调用 PayOrderEvent
   - 显示"支付中..."加载框
   - 调用对应支付SDK

4. **支付结果**：
   - PaymentCompletedState：支付成功
   - PaymentFailedState：支付失败
   - 跳转到支付结果页面

### 支付方式
- 支付宝支付（默认）
- 微信支付（可配置是否可用）
- 余额支付（预留）
- 积分支付（预留）

### 支付相关字段
- payType：支付类型
- payTradeNo：支付单号
- payTime：支付时间

## 十四、业务规则补充

1. **价格计算**：
   - 总价 = 商品价格 × 数量
   - 实付款 = 总价 + 运费 - 优惠金额

2. **权限控制**：
   - 买家只能操作自己的订单
   - 卖家只能操作属于自己店铺的订单
   - 平台管理员可以查看所有订单

3. **时间限制**：
   - 自动取消时间：可配置（默认30分钟）
   - 自动确认收货时间：可配置
   - 售后申请时限：订单完成后一定时间内

4. **并发控制**：
   - 使用 @RepeatSubmit 注解防止重复提交
   - 使用事务隔离级别控制并发操作

5. **通知机制**：
   - 关键状态变更时发送站内通知
   - 支持微信模板消息通知（需配置）

## 总结

订单系统采用状态机模式管理订单生命周期，通过事件驱动实现业务解耦。系统支持买卖双方不同视角的操作，提供完整的订单管理、支付、退款、售后等功能。前后端分离架构，后端提供RESTful API，前端使用Flutter BLoC模式管理状态，实现了良好的用户体验和系统可维护性。
